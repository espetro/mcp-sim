# Screens: user flows and configuration surfaces

Two layers, mirroring the product/config split:

1. **Product flows** (`flows.md` here): what a user (human or agent) does
   with mcp-sim, step by step, at the MCP-client level.
2. **Low-level surfaces** (`surfaces.md` here): every place a human touches
   configuration: CLI flags, YAML keys, env vars, file locations.

Keep both accurate at every commit. Stale maps are worse than none.
